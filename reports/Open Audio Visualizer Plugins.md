# Reuse Visualizer Engines Without Assuming Permission

There are several useful open-source visualizer projects, but the best starting point for a future Linux, Windows 64-bit, and Android product is **projectM**, a cross-platform MilkDrop-compatible rendering library—not the old player bundles themselves. **Butterchurn** is a permissively licensed WebGL alternative; modern **AVS** ports and narrower tools such as CAVA and GLava offer effect and audio-analysis ideas. Keep the renderer’s code license separate from the rights to presets, shaders, textures, images, plugins, and branding. A program’s age, free download, or missing copyright notice does not establish permission to copy or redistribute it.

## projectM is the strongest shared engine for three platforms

The official projectM project describes a C++ library that accepts PCM audio, parses MilkDrop presets, performs beat/FFT analysis, and renders through OpenGL. Its documented targets include Linux, Windows, and Android; the core is LGPL-2.1, so integration and distribution must follow that license and preserve applicable notices. This makes it the most credible common rendering engine to prototype for the future cross-platform product. However, adopting it would be a substantial renderer change from this repository’s Python/pygame Life Explosion implementation, and MilkDrop presets do not reproduce Life Explosion’s `.xpl` particle-cycle semantics. Test compatibility and performance with the actual presets and devices before choosing it ([projectM core and license](https://github.com/projectM-visualizer/projectm); [official build/platform guide](https://github.com/projectM-visualizer/projectm/blob/master/docs/building.rst)).

The projectM SDL viewer is a standalone desktop program, but it has its own GPL-3.0 license; do not confuse the viewer’s terms with the LGPL core’s terms. **Butterchurn** implements MilkDrop in WebGL under MIT and is attractive if a future product uses a browser or embedded WebView. It is not a native screensaver framework and requires WebGL 2. For effect research, the modern **vis_avs** port documents BSD-3 licensing and AVS-style effect chains, but its Linux frontend is still work in progress and 64-bit/product maturity is limited. **CAVA** (MIT) is useful for spectrum smoothing and audio-analysis ideas; **GLava** (GPL-3.0) provides Linux/OpenGL shader examples, but is Linux/X11-focused and less suitable as portable product code ([projectM SDL frontend](https://github.com/projectM-visualizer/frontend-sdl-cpp); [Butterchurn](https://github.com/jberg/butterchurn); [vis_avs](https://github.com/grandchild/vis_avs); [CAVA](https://github.com/karlstav/cava); [GLava](https://github.com/jarcode-foss/glava)).

## Winamp and Poweramp are references, not blanket asset licenses

**MilkDrop** is the classic Winamp visualizer: its creator describes beat-triggered effects and GPU pixel shaders, and publishes a MilkDrop 2.25c source route with a BSD license. That is a potentially useful code reference, but it is an older Win32 implementation; do not assume every later bundled Winamp/MilkDrop build, dependency, preset, or texture shares that same license. The original **AVS** is valuable as a library of composable effect concepts; the modern BSD-3 community port is a more tractable code reference than copying legacy binaries or packs ([Geiss’s MilkDrop page](https://www.geisswerks.com/milkdrop/); [MilkDrop 2 SourceForge project](https://sourceforge.net/projects/milkdrop2/); [modern AVS port and provenance notes](https://github.com/grandchild/vis_avs)).

**Poweramp** is an Android player with MilkDrop-compatible visualizations and a documented preset-pack mechanism. Its public API license is scoped to software that communicates with Poweramp; that can suit a Poweramp add-on, not a standalone Linux/Windows/Android visualizer. It does not grant rights to Poweramp’s bundled presets or third-party `.milk` files and textures. For a standalone Android app, projectM is a more portable foundation. Feeding PCM from the app’s own player is the most predictable path; visualizing other apps is subject to Android capture permission, user consent, and source-app policy ([Poweramp API and preset example](https://github.com/maxmpz/powerampapi); [Poweramp API license](https://github.com/maxmpz/powerampapi/blob/master/LICENSE.txt); [Android playback capture rules](https://developer.android.com/media/platform/av-capture)).

## Audit code, presets, textures, and plugins independently

An engine license covers the code described by that license; it does not automatically clear preset files, artwork, shaders, texture packs, fonts, third-party effects, or logos. projectM distributes its core separately from preset collections. The Cream of the Crop MilkDrop pack acknowledges that most presets lack explicit author licenses and explains that its public-domain assumption is the pack maintainers’ position—not a separate grant from every creator. Treat such packs as **uncleared for redistribution** unless you can confirm rights for the specific content. Likewise, inspect AVS effect provenance and dependencies, and do not treat a preset’s availability inside Winamp or Poweramp as permission to extract and ship it ([projectM preset distribution notes](https://github.com/projectM-visualizer/projectm); [Cream of the Crop license statement](https://github.com/projectM-visualizer/presets-cream-of-the-crop/blob/master/LICENSE.md); [AVS provenance notes](https://github.com/grandchild/vis_avs)).

Old software is not automatically public domain. In the United States, the Copyright Office says protection generally begins when an original work is fixed, and many post-1977 works last for the author’s life plus 70 years; it also explains that terms vary by work and publication history. These U.S. sources illustrate why age alone is not a safe test, but they do not settle rights in India or any other jurisdiction ([U.S. Copyright Office: duration](https://www.copyright.gov/help/faq/faq-duration.html); [U.S. Copyright Office: general copyright facts](https://www.copyright.gov/help/faq/faq-general.html)). This is a technical reuse survey, not legal advice or a rights clearance.

## A practical path for this Life Explosion project

For the current Linux program, keep the recovered `.xpl` timing and particle renderer as the product’s distinctive core; study MilkDrop/AVS for independently implemented ideas such as feedback warping, procedural waves, shader color effects, and beat accents. If a shared engine becomes the priority for Windows 64-bit and Android, prototype projectM as an optional backend and compare its deployment obligations and rendering behavior against the current implementation. Butterchurn is a reasonable alternative only if adopting a WebGL/WebView architecture is acceptable. Android playback capture is not guaranteed for every player or track, so plan for internal PCM playback as well as an explicitly consented capture mode ([projectM](https://github.com/projectM-visualizer/projectm); [Android capture guide](https://developer.android.com/media/platform/av-capture)).

Before shipping reused material, record its exact source URL, author, version or commit, license/permission, modifications, and dependencies in an asset and third-party notice manifest. Preserve license and attribution files; audit each library and platform frontend separately; and use original or explicitly licensed presets, textures, and branding where provenance is uncertain. Treat source code, preset definitions, shader text, bundled art, and trademarks as separate review items. These steps make a reuse decision traceable, while any commercial or multi-country release with unclear assets should receive jurisdiction-specific rights review.
